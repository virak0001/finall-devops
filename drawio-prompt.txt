━━━ PAGE 2: "CI/CD Pipeline" ━━━

Branch model: develop to dev, testing to uat, main to prod.

Top lane, one box per stage:
Developer git push > GitHub > signed webhook > Jenkins multibranch job (auth-api / core-api / client-side, shared library "platform")

Stages, marking the gates with a red "fails the build" badge:
1. Prepare: version tag from git describe
2. Secret scan: Gitleaks [gate]
3. Unit tests: npm ci + test:cov [gate]
4. Dependency scan: Trivy fs, fixable CRITICAL [gate]
5. SonarQube analysis, then Quality gate [gate]
6. Build image: docker build with revision, version, built-by and build-url labels
7. Image scan: Trivy image, fixable CRITICAL [gate]

Draw a dashed divider labelled "develop / testing / main only", then:
8. Push to ECR: immutable tag, skipped if this commit already exists
9. Approve prod: main only, a manual approval diamond
10. Deploy, as a sub-flow:
    a. Jenkins commits the new tag to helm/env/<env>.yaml in the cluster repo, with who/what/when as git trailers
    b. Argo CD pulls the repo. dev and uat auto-sync; for prod, Jenkins triggers the sync
    c. Jenkins waits for Synced + Healthy, then checks the running image
    d. Smoke test through the public URL
    e. Decision: pass or fail

Outcomes:
- Pass: record SUCCEEDED
- Fail on uat or prod: automatic rollback by committing the previous tag
- Fail on dev: the release stays in place for inspection
- Every result goes to the CloudWatch deployments log and Telegram
- Failure statuses trigger a metric filter, then the alarm, then SNS email

Second, smaller lane, "release job" (manual, Build with Parameters: SERVICE, TARGET, ACTION = promote or rollback):
Promote copies the tag dev > uat > prod with no rebuild. The tag must exist in ECR, and prod needs approval. It then joins the same Deploy sub-flow.

Callout: "Build once, promote the same image. A fast-forward merge keeps the same commit and the same tag."

Environment promotion strip across the bottom:
helm/env/dev.yaml > helm/env/uat.yaml > helm/env/prod.yaml, each going to its own cluster.
